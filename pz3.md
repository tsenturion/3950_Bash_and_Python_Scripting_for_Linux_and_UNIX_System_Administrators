# **Практическое задание № 3. Продвинутый Bash: автоматизация резервного копирования и обработки файлов**

**Модуль 3. Продвинутый Bash**

## **Цель**

Освоить продвинутые возможности Bash для создания надёжных сценариев автоматизации, способных обрабатывать ошибки, проверять входные данные, управлять файлами и выполнять задачи по расписанию.

В ходе практической работы необходимо:

- Научиться обнаруживать и обрабатывать ошибки выполнения Bash-скриптов.
- Освоить применение регулярных выражений для проверки имён файлов и анализа их содержимого.
- Научиться выполнять автоматизированный поиск, копирование, архивирование и обработку файлов.
- Освоить использование `trap`, кодов завершения и журналирования для повышения надёжности скриптов.
- Научиться создавать периодические задания с помощью `cron`.
- Освоить планирование однократных задач с помощью `at`.
- Разработать систему автоматического резервного копирования с проверкой результатов и фиксацией ошибок.

## **Задание (шаги)**

### **Шаг 1. Подготовка проекта и тестовых данных**

Необходимо создать рабочую среду для разработки системы автоматического резервного копирования.

1. Создать рабочий каталог `bash_backup_manager`.
2. Внутри него создать следующие подкаталоги:
   - `incoming` — исходные файлы для обработки;
   - `backup` — готовые резервные копии;
   - `logs` — журналы выполнения и ошибок;
   - `reports` — отчёты о результатах;
   - `scripts` — Bash-скрипты;
   - `tmp` — временные файлы.
3. В каталоге `scripts` создать файл `backup_manager.sh`.
4. Добавить в начало скрипта строку `#!/usr/bin/env bash`.
5. Создать в каталоге `incoming` следующие файлы:
   - `report_2026-11-14.txt`;
   - `report_2026-11-15.txt`;
   - `report_2026-11-16.txt`;
   - `report_latest.txt`;
   - `notes.txt`.
6. Заполнить первые три файла тестовыми записями с уровнями `INFO`, `WARN` и `ERROR`.
7. Добавить в один из файлов не менее двух записей с уровнем `ERROR`.
8. Создать внутри `incoming` дополнительный вложенный каталог `old_reports`.
9. Проверить структуру проекта с помощью `find` и `ls`.

**Ожидаемый результат:** Создана структура проекта с тестовыми файлами, среди которых присутствуют подходящие и неподходящие для обработки данные.

### **Шаг 2. Проверка параметров и обработка ошибок**

Необходимо реализовать проверки, которые предотвращают выполнение скрипта с некорректными параметрами.

```

--help             Справочная информация
```

Реализовать следующую логику:

2. Проверять существование исходного каталога.
3. Проверять доступность исходного каталога для чтения.
4. Проверять существование каталога для резервных копий.
5. Если каталог для резервных копий отсутствует, создавать его.
6. Проверять доступность выходного каталога для записи.
7. Проверять наличие необходимых утилит, включая `find`, `grep` и `tar`.
8. При обнаружении ошибки выводить понятное диагностическое сообщение.
9. Записывать информацию об ошибке в `logs/error.log`.
10. Завершать выполнение с ненулевым кодом при критических ошибках.

Дополнительно реализовать обработку неизвестных параметров командной строки.

**Ожидаемый результат:** Скрипт обнаруживает некорректные параметры и проблемы с каталогами, сообщает об их причинах и не продолжает выполнение при критических ошибках.

Скрипт должен обрабатывать только файлы, названия которых соответствуют шаблону:

9. Добавить дату и время создания архива в его название.

## **Подсказки по ключевым частям**

### **1. Обработка ошибок Bash**

Для повышения надёжности скриптов можно использовать:

```
set -euo pipefail
```

Назначение параметров:

| Параметр      | Описание                                                                |
| ------------- | ----------------------------------------------------------------------- |
| `-e`          | Завершение при некоторых ошибках выполнения команд                      |
| `-u`          | Ошибка при обращении к неопределённым переменным                        |
| `-o pipefail` | Возврат ошибки конвейера, если одна из его команд завершилась неуспешно |

Важно учитывать, что `set -e` не гарантирует завершение при любой ошибке: его поведение зависит от контекста выполнения команды.

Некоторые команды используют ненулевой код завершения для обозначения обычных ситуаций. Например, `grep` возвращает код `1`, если совпадения отсутствуют. Такие случаи необходимо обрабатывать отдельно.

Для явного завершения скрипта можно использовать:

```
exit 1
```

Код `0` обычно обозначает успешное выполнение.

### **2. Использование trap**

Команда `trap` позволяет назначать действия, выполняемые при получении сигналов или при завершении скрипта.

Пример:

```
cleanup() {
    echo "Очистка временных ресурсов"
}

trap cleanup EXIT
```

Обработчик `EXIT` выполняется при обычном завершении оболочки, в том числе при завершении из-за многих ошибок. Он не может обработать принудительное завершение сигналом `SIGKILL`.

Для удаления временных файлов необходимо использовать проверенные пути, чтобы исключить случайное удаление посторонних данных.

### **3. Регулярные выражения**

Для проверки формата названия файла можно использовать следующее выражение:

```
^report_[0-9]{4}-[0-9]{2}-[0-9]{2}\.txt$
```

Основные элементы:

| Элемент | Значение                |
| ------- | ----------------------- |
| `^`     | Начало строки           |
| `$`     | Конец строки            |
| `[0-9]` | Цифра                   |
| `{4}`   | Ровно четыре повторения |
| `{2}`   | Ровно два повторения    |
| `\.`    | Буквальная точка        |

Для проверки соответствия регулярному выражению Bash поддерживает оператор `=~` внутри конструкции `[[ ... ]]`.

Проверка формата даты регулярным выражением не гарантирует существование самой даты. Например, `2026-13-40` соответствует формату, но не является корректной календарной датой.

### **4. Работа с файлами и каталогами**

Полезные команды:

| Команда     | Назначение                           |
| ----------- | ------------------------------------ |
| `find`      | Поиск файлов и каталогов             |
| `cp`        | Копирование файлов                   |
| `mkdir -p`  | Создание каталогов                   |
| `mktemp -d` | Создание временного каталога         |
| `tar -czf`  | Создание сжатого архива              |
| `tar -tzf`  | Просмотр содержимого архива          |
| `du -h`     | Определение занимаемого пространства |
| `stat`      | Получение информации о файле         |

При обработке имён файлов рекомендуется учитывать наличие пробелов и специальных символов. Для безопасного чтения результатов `find` можно использовать разделитель NUL:

```
find incoming -maxdepth 1 -type f -print0
```

Результат такой команды можно читать через `read -r -d ''`.

### **5. Журналирование**

Для добавления времени к сообщению можно использовать:

```
date "+%Y-%m-%d %H:%M:%S"
```

Для записи информационных сообщений и ошибок рекомендуется использовать отдельные функции.

Ошибки должны направляться в stderr и фиксироваться в журнале, чтобы их можно было обнаружить при автоматическом выполнении скрипта.

### **6. Планирование с помощью cron**

Формат записи:

```
минута час день_месяца месяц день_недели команда
```

Пример:

```
30 2 * * * /path/to/script.sh
```

Такая запись запускает скрипт ежедневно в 02:30 по времени, используемому планировщиком.

Для тестирования можно использовать:

```
*/5 * * * * /path/to/script.sh
```

При настройке необходимо учитывать, что пользовательский `crontab` может уже содержать другие задания. Их нельзя удалять или изменять без необходимости.

### **7. Планирование с помощью at**

Для постановки однократного задания используется команда `at`.

Пример:

```
echo "/path/to/script.sh" | at now + 2 minutes
```

Дополнительные команды:

```
atq
atrm 3
```

`atq` отображает очередь заданий, а `atrm` позволяет удалить задание по его идентификатору.

Для выполнения запланированных заданий необходима работающая служба `atd`.

### **8. Проверка синтаксиса и отладка**

Проверка синтаксиса:

```
bash -n scripts/backup_manager.sh
```

Отладочный запуск:

```
bash -x scripts/backup_manager.sh
```

Для анализа потенциальных ошибок и проблем переносимости также можно использовать ShellCheck.

## **Советы по улучшению работы**

1\. **Использование строгих проверок.** Проверять не только существование файлов и каталогов, но и возможность чтения, записи и выполнения необходимых операций.

2\. **Разделение кода на функции.** Проверку параметров, поиск файлов, архивирование, журналирование и формирование отчётов рекомендуется реализовать в отдельных функциях.

3\. **Безопасное использование временных файлов.** Для создания уникальных временных каталогов рекомендуется использовать `mktemp -d`, а для их очистки — обработчик `trap`.

4\. **Корректная работа с путями.** Пути необходимо заключать в кавычки, особенно если они могут содержать пробелы или специальные символы.

5\. **Проверка результатов выполнения команд.** Успешный запуск команды архивирования не должен быть единственным критерием корректности резервной копии. Рекомендуется дополнительно проверять содержимое архива.

6\. **Использование уникальных имён архивов.** Для исключения перезаписи предыдущих копий можно добавлять к имени архива дату, время и дополнительный уникальный идентификатор.

7\. **Разделение информационных сообщений и ошибок.** Рекомендуется использовать разные журналы или уровни сообщений, позволяющие быстро обнаруживать причины сбоев.

8\. **Защита от одновременного запуска.** Если резервное копирование выполняется по расписанию, полезно предусмотреть защиту от ситуаций, когда предыдущий запуск ещё не завершился.

9\. **Автоматическая очистка старых резервных копий.** В качестве дополнительного улучшения можно реализовать удаление архивов старше заданного количества дней, предварительно ограничив поиск только каталогом резервных копий.

10\. **Контроль успешности запланированных заданий.** Для регулярных запусков можно предусмотреть отдельную проверку появления новых архивов и запись предупреждения при отсутствии ожидаемого результата.
