# **Практическое задание № 5. Автоматизация системного администрирования с помощью Python**

**Модуль 5. Автоматизация задач на Python**

## **Цель**

Освоить инструменты Python для автоматизации задач системного администрирования, научиться управлять системными командами, анализировать журналы, выполнять удалённые операции через SSH и создавать полноценные утилиты командной строки.

В ходе практической работы необходимо:

- Научиться запускать системные команды из Python с помощью модуля `subprocess`.
- Освоить получение стандартного вывода, обработку ошибок и контроль времени выполнения внешних процессов.
- Научиться анализировать текстовые журналы с использованием строковых операций и регулярных выражений.
- Освоить подключение к удалённым Linux-серверам по SSH с помощью библиотеки `paramiko`.
- Научиться выполнять удалённые команды и получать результаты их выполнения.
- Освоить разработку CLI-интерфейсов с использованием модуля `argparse`.
- Разработать консольное приложение, объединяющее локальную диагностику, удалённую проверку сервера и анализ журналов.

## **Задание (шаги)**

### **Шаг 1. Подготовка проекта и рабочего окружения**

Необходимо создать рабочую среду для разработки административной CLI-утилиты.

1. Создать каталог `python_admin_monitor`.
2. Внутри него создать следующие подкаталоги:
   - `data` — тестовые журналы и текстовые файлы;
   - `reports` — результаты диагностики и отчёты;
   - `logs` — журналы работы самой утилиты;
   - `config` — дополнительные настройки;
   - `tests` — материалы для тестирования.
3. Создать основной файл `admin_monitor.py`.
4. Создать виртуальное окружение Python с помощью `venv`.
5. Активировать виртуальное окружение.
6. Установить библиотеку `paramiko` с помощью `pip`.
7. Создать файл `requirements.txt` с зависимостями проекта.
8. Проверить доступность модулей `subprocess`, `argparse`, `json`, `re`, `pathlib` и `datetime`.
9. Проверить версию установленного Python.
10. Создать файл `README.md` с кратким описанием назначения программы и условий запуска.

**Требования к окружению:** Python 3.10 или новее, Linux либо WSL с доступными стандартными утилитами Linux. Для проверки удалённых операций потребуется тестовый SSH-сервер, к которому разрешён доступ.

**Ожидаемый результат:** Подготовлен Python-проект с установленными зависимостями и необходимой структурой каталогов.

### **Шаг 2. Запуск системных команд с помощью subprocess**

Необходимо реализовать механизм локальной диагностики Linux-системы.

**Часть А. Выполнение команд**

Создать функцию `run_local_command()`, которая получает команду и её аргументы в виде списка и запускает соответствующий процесс.

С помощью `subprocess` выполнить следующие системные команды:

| Команда    | Получаемая информация                |
| ---------- | ------------------------------------ |
| `uname -s` | Название ядра операционной системы   |
| `hostname` | Имя компьютера                       |
| `uptime`   | Время работы системы и нагрузка      |
| `df -h`    | Использование дискового пространства |
| `whoami`   | Имя текущего пользователя            |

Для каждой команды необходимо:

1. Запустить команду из Python.
2. Получить стандартный вывод `stdout`.
3. Получить поток ошибок `stderr`.
4. Определить код завершения `returncode`.
5. Проверить успешность выполнения.
6. Вывести результат в терминал.
7. Сохранить результат в структуру данных Python.
8. Предусмотреть ограничение времени выполнения команды.

**Часть Б. Обработка ошибок**

Реализовать обработку следующих ситуаций:

1. Команда успешно завершилась.
2. Команда завершилась с ненулевым кодом.
3. Указанная программа отсутствует в системе.
4. Время выполнения превысило установленный предел.
5. Во время запуска возникла ошибка операционной системы.

При возникновении ошибки необходимо записывать её описание в `logs/monitor.log`.

**Ограничение:** Запускать разрешается только заранее определённые диагностические команды. Необходимо использовать `shell=False` и передавать аргументы списком, а не формировать команду оболочки из пользовательских строк.

Пример результата:

Command: whoami
Return code: 0

**Ожидаемый результат:** Программа выполняет диагностические системные команды, получает результаты и корректно обрабатывает ошибки запуска.

**Ожидаемый результат:** Программа разбирает журналы, извлекает структурированные данные, рассчитывает статистику и отделяет некорректные записи от корректных.

### **Шаг 4. Автоматизированная проверка удалённого сервера через SSH**

Необходимо реализовать удалённую диагностику Linux-сервера с помощью библиотеки `paramiko`.

Для выполнения задания использовать тестовый SSH-сервер, предоставленный преподавателем, либо собственную учебную виртуальную машину с настроенным SSH-доступом. Допускается подключение к `localhost`, если на локальной машине работает SSH-сервер.

**Часть А. Подготовка SSH-подключения**

1. Проверить доступность SSH-сервера.
2. Подготовить адрес сервера и имя пользователя.
3. Убедиться, что подключение разрешено.
4. Настроить аутентификацию по SSH-ключу.
5. Проверить подключение стандартной командой `ssh`.
6. Сверить ключ SSH-сервера с доверенным значением и добавить его в `known_hosts` при подтверждённом соответствии.
7. Установить соединение из Python через `paramiko.SSHClient`.

Необходимо использовать проверку ключа сервера. Запрещено автоматически доверять неизвестным ключам через `AutoAddPolicy()`.

**Часть Б. Выполнение удалённых команд**

Создать функцию `run_remote_command()`, которая выполняет заранее определённые команды через SSH.

На удалённом сервере выполнить:

| Команда    | Назначение                                |
| ---------- | ----------------------------------------- |
| `hostname` | Получить имя сервера                      |
| `uptime`   | Проверить время работы                    |
| `df -h`    | Проверить дисковое пространство           |
| `free -h`  | Получить информацию об оперативной памяти |
| `whoami`   | Проверить пользователя подключения        |

Необходимо:

1. Установить SSH-соединение.
2. Выполнить команду с помощью `exec_command()`.
3. Получить стандартный вывод.
4. Получить сообщения об ошибках.
5. Определить код завершения удалённой команды.
6. Сохранить результаты в словарь.
7. Закрыть SSH-соединение после завершения диагностики.

**Часть В. Обработка ошибок SSH**

Предусмотреть ситуации:

1. Сервер недоступен.
2. Указан неправильный порт.
3. Не удалось пройти аутентификацию.
4. Ключ сервера не прошёл проверку.
5. Соединение было прервано.
6. Удалённая команда завершилась с ошибкой.
7. Истекло допустимое время ожидания.

При ошибке соединения программа должна выводить диагностическое сообщение, фиксировать проблему в журнале и корректно освобождать ресурсы.

Пример успешной диагностики:

```
========== REMOTE SERVER CHECK ==========

Host: 192.0.2.10
User: student
Port: 22

SSH connection: SUCCESS

Remote hostname: test-server
Remote uptime: 2 days
Disk check: SUCCESS
Memory check: SUCCESS

Remote diagnostics completed.
```

Адрес 192.0.2.10 приведён исключительно как пример и должен быть заменён адресом доступного учебного сервера.

**Ограничения:** Запрещается выполнять удалённые команды, изменяющие системные настройки, удаляющие файлы или завершающие процессы. Пароли и приватные SSH-ключи нельзя размещать в исходном коде, отчётах или отправляемом проекте.

**Ожидаемый результат:** Программа выполняет удалённые диагностические команды через SSH, получает результаты и обрабатывает ошибки подключения.

### **Шаг 5. Создание интерфейса командной строки**

Необходимо реализовать CLI-интерфейс с помощью стандартного модуля `argparse`.

Программа должна поддерживать следующие действия:

| Действие      | Назначение                     |
| ------------- | ------------------------------ |
| `check-local` | Диагностика локальной системы  |
| `analyze`     | Анализ журнала событий         |
| `check-ssh`   | Диагностика удалённого сервера |
| `full`        | Комплексная диагностика        |
| `--help`      | Справочная информация          |

Реализовать следующие параметры:

| Параметр    | Описание                               |
| ----------- | -------------------------------------- |
| `--log`     | Путь к анализируемому журналу          |
| `--host`    | Адрес SSH-сервера                      |
| `--user`    | Имя удалённого пользователя            |
| `--port`    | SSH-порт, по умолчанию 22              |
| `--key`     | Путь к приватному SSH-ключу            |
| `--output`  | Путь к итоговому отчёту                |
| `--timeout` | Максимальное время ожидания в секундах |

**Примеры запуска:**

Локальная диагностика:

```
python admin_monitor.py check-local
```

Анализ журнала:

```
python admin_monitor.py analyze --log data/application.log
```

Удалённая диагностика:

```
python admin_monitor.py check-ssh \
    --host 192.0.2.10 \
    --user student \
    --key ~/.ssh/id_ed25519
```

Комплексная проверка:

```
python admin_monitor.py full \
    --log data/application.log \
    --host 192.0.2.10 \
    --user student \
    --key ~/.ssh/id_ed25519 \
    --output reports/full_report.json
```

Необходимо реализовать:

1. Создание парсера аргументов.
2. Определение выбранного действия.
3. Проверку обязательных параметров для каждого действия.
4. Проверку допустимости значения `--port` от 1 до 65535.
5. Проверку положительного значения `--timeout`.
6. Автоматический вывод справочной информации.
7. Обработку некорректных аргументов.
8. Вызов соответствующих функций на основании переданных параметров.
9. Возврат корректного кода завершения программы.

Для `check-ssh` параметры `--host` и `--user` обязательны, а для `analyze` обязателен `--log`. Для `full` необходимы параметры обеих проверок.

**Ожидаемый результат:** Программа управляется аргументами командной строки и может использоваться в Bash-скриптах и автоматизированных сценариях без интерактивного ввода.

### **Шаг 6. Создание комплексной диагностики**

Необходимо объединить разработанные функции в единый механизм проверки системы.

При выполнении действия `full` программа должна последовательно:

1. Проверить переданные параметры командной строки.
2. Выполнить локальную диагностику с помощью `subprocess`.
3. Сохранить результаты выполнения локальных команд.
4. Прочитать и проанализировать указанный журнал событий.
5. Сформировать статистику ошибок и предупреждений.
6. Установить SSH-соединение с удалённым сервером.
7. Выполнить удалённые диагностические команды.
8. Сохранить полученные результаты.
9. Сформировать общий отчёт.
10. Вывести итоговый статус выполнения.

Важное требование: если одна из независимых проверок завершилась с ошибкой, остальные проверки должны продолжить выполнение, если для них доступны необходимые данные.

Использовать следующие статусы:

| Статус    | Значение                                             |
| --------- | ---------------------------------------------------- |
| `SUCCESS` | Все запрошенные проверки выполнены                   |
| `PARTIAL` | Часть проверок завершилась с ошибками                |
| `FAILED`  | Ни одна из запрошенных проверок не выполнена успешно |

Результаты должны сохраняться раздельно для каждого этапа диагностики.

**Ожидаемый результат:** Разработан единый механизм, который выполняет локальную проверку, анализ логов и удалённую диагностику, не теряя результаты успешных этапов при возникновении ошибок в других.

Для записи данных использовать стандартный модуль `json`. При сохранении кириллического текста обеспечить корректное представление символов.

Необходимо проверить, что созданный JSON-файл может быть повторно прочитан программой.

**Ожидаемый результат:** Программа формирует структурированный машиночитаемый отчёт, пригодный для дальнейшего анализа и интеграции с другими инструментами автоматизации.

### **Шаг 8. Журналирование и обработка ошибок**

Необходимо реализовать единый механизм регистрации событий работы программы.

Создать функцию `log_event()`, которая принимает уровень сообщения и текст события.

Использовать следующие уровни:

- `INFO` — информационные сообщения;
- `WARNING` — предупреждения;
- `ERROR` — ошибки выполнения.

В журнал `logs/monitor.log` необходимо записывать:

1. Запуск программы.
2. Выбранное действие CLI.
3. Начало и завершение локальной диагностики.
4. Результаты анализа журналов.
5. Попытки SSH-подключения и их результат.
6. Ошибки выполнения команд.
7. Ошибки чтения и записи файлов.
8. Итоговый статус программы.

Пример:

```
[2026-11-19 12:30:00] INFO: Program started
[2026-11-19 12:30:01] INFO: Local diagnostics started
[2026-11-19 12:30:02] INFO: Local diagnostics completed
[2026-11-19 12:30:03] INFO: Log analysis completed
[2026-11-19 12:30:05] ERROR: SSH connection timeout
[2026-11-19 12:30:05] WARNING: Diagnostic completed partially
```

## **Подсказки по ключевым частям**

### **1. Запуск подпроцессов**

Для запуска системных команд можно использовать `subprocess.run()`.

```
import subprocessresult = subprocess.run(    ["uname", "-s"],    capture_output=True,    text=True,    timeout=10,    check=False)print(result.stdout)print(result.stderr)print(result.returncode)
```

Основные параметры:

| Параметр         | Назначение                                            |
| ---------------- | ----------------------------------------------------- |
| `args`           | Команда и аргументы                                   |
| `capture_output` | Перехват stdout и stderr                              |
| `text`           | Получение результатов в виде строк                    |
| `timeout`        | Ограничение времени выполнения                        |
| `check`          | Генерация исключения при ненулевом коде, если включён |
| `cwd`            | Рабочий каталог процесса                              |
| `env`            | Переменные окружения процесса                         |

При использовании `check=True` ненулевой код завершения вызывает `subprocess.CalledProcessError`. Превышение времени ожидания вызывает `subprocess.TimeoutExpired`.

Подробное описание: [Документация Python — subprocess](https://docs.python.org/3/library/subprocess.html).

### **2. Парсинг журналов**

Для разделения строки журнала на поля можно использовать `split()`.

```
line = "2026-11-19 10:00:01 ERROR db connection_failed"parts = line.split()if len(parts) == 5:    date, time, level, component, event = parts    print(level, component, event)
```

Перед обработкой необходимо проверять количество полей.

Если формат журнала допускает пробелы внутри текста события, потребуется изменить подход к разбору, например ограничить число разделений или использовать регулярные выражения.

### **3. Регулярные выражения**

Для проверки структуры записи можно использовать модуль `re`.

```
import repattern = (    r"^\d{4}-\d{2}-\d{2} "    r"\d{2}:\d{2}:\d{2} "    r"(INFO|WARN|ERROR) "    r"\w+ \w+$")
```

Для проверки полного соответствия рекомендуется использовать `re.fullmatch()`.

Следует учитывать, что регулярное выражение проверяет структуру строки, но не гарантирует корректность календарной даты. Для дополнительной проверки можно использовать `datetime.strptime()`.

### **4. Подключение по SSH**

Для работы с удалённым сервером используется `paramiko.SSHClient`.

```
import paramikoclient = paramiko.SSHClient()client.load_system_host_keys()client.set_missing_host_key_policy(    paramiko.RejectPolicy())
```

После загрузки доверенных ключей можно устанавливать соединение, используя адрес сервера, имя пользователя и SSH-ключ.

Для выполнения удалённой команды:

```
stdin, stdout, stderr = client.exec_command(    "hostname",    timeout=10)output = stdout.read().decode("utf-8")errors = stderr.read().decode("utf-8")exit_code = stdout.channel.recv_exit_status()
```

После завершения работы необходимо закрывать соединение с помощью `client.close()`. В полноценной реализации закрытие должно выполняться даже при возникновении исключений.

Важно: `exec_command()` принимает командную строку для удалённой стороны, поэтому произвольные пользовательские данные нельзя напрямую включать в команды. Для задания достаточно фиксированного набора диагностических команд.

Подробнее: [Документация Paramiko — SSHClient](https://docs.paramiko.org/en/stable/api/client.html).

### **5. Создание CLI-интерфейса**

Для обработки аргументов командной строки можно использовать `argparse`.

```
import argparseparser = argparse.ArgumentParser(    description="System monitoring utility")parser.add_argument(    "--host",    type=str,    help="SSH server address")parser.add_argument(    "--port",    type=int,    default=22,    help="SSH port")args = parser.parse_args()print(args.host)print(args.port)
```

`argparse` поддерживает обязательные параметры, значения по умолчанию, автоматическую справку и проверку типов. Проверки диапазонов, например допустимого SSH-порта, необходимо реализовать дополнительно.

Подробнее: [Документация Python — argparse](https://docs.python.org/3/library/argparse.html).
