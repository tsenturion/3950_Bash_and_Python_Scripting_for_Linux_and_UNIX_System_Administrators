# **Практическое задание № 1. Основы Linux/UNIX для автоматизации**

**Модуль 1. Основы Linux/UNIX для автоматизации**

## **Цель**

Освоить базовые инструменты командной строки Linux/UNIX и научиться применять их для автоматизации повседневных задач системного администрирования.

В ходе практической работы необходимо:

- Научиться перемещаться по файловой системе, создавать каталоги, просматривать и изменять файлы.
- Освоить стандартные потоки ввода, вывода и ошибок, а также операторы перенаправления.
- Научиться объединять команды в конвейеры и обрабатывать текстовые данные с помощью `grep`, `sed` и `awk`.
- Освоить просмотр, запуск, остановку и управление фоновыми процессами.
- Создать Bash-скрипт, который автоматически анализирует журналы событий и формирует отчёт.

## **Подсказки по ключевым частям**

### **1. Навигация и файловые операции**

Для работы с каталогами и файлами используются команды:

| Команда    | Назначение                              |
| ---------- | --------------------------------------- |
| `pwd`      | Определение текущего каталога           |
| `cd`       | Переход между каталогами                |
| `mkdir -p` | Создание каталогов, включая вложенные   |
| `touch`    | Создание пустого файла                  |
| `ls -la`   | Подробный просмотр содержимого каталога |
| `cat`      | Вывод содержимого файла                 |
| `wc -l`    | Подсчёт количества строк                |

Для записи результатов команд в файлы необязательно использовать текстовый редактор. Результат выполнения команды можно направить непосредственно в нужный файл.

### **2. Перенаправление потоков**

В Linux/UNIX предусмотрены три стандартных потока:

| Поток  | Дескриптор | Назначение               |
| ------ | ---------- | ------------------------ |
| stdin  | `0`        | Стандартный ввод         |
| stdout | `1`        | Стандартный вывод        |
| stderr | `2`        | Стандартный вывод ошибок |

Основные операторы перенаправления:

```
>       # Перезапись файла
>>      # Добавление в конец файла
<       # Чтение ввода из файла
2>      # Перенаправление ошибок
2>&1    # Направление stderr туда же, куда stdout
|       # Передача stdout одной команды на stdin другой
```

При объединении stdout и stderr порядок перенаправлений имеет значение.

### **3. Фильтрация данных**

Команда `grep` предназначена для поиска строк по заданному шаблону.

`sed` позволяет преобразовывать текстовый поток, заменять фрагменты текста и выбирать или исключать строки.

`awk` позволяет обрабатывать данные по столбцам, выполнять вычисления и формировать отчёты.

При анализе предоставленного журнала в `awk`:

- `$1` — дата;
- `$2` — время;
- `$3` — уровень события;
- `$4` — компонент;
- `$5` — название события;
- `$6` — продолжительность операции.

Для вычисления среднего значения можно использовать переменные накопления суммы и количества, а итоговое вычисление выполнить в блоке `END`. Необходимо предусмотреть ситуацию, когда подходящих записей нет, чтобы избежать деления на ноль.

### **4. Конвейеры**

Конвейер позволяет последовательно передавать данные между командами.

Например:

```
cat logs/system.log | grep "ERROR" | wc -l
```

Эта команда передаёт содержимое журнала в `grep`, который выбирает строки с ошибками, после чего `wc` подсчитывает количество полученных строк.

При решении более сложных задач можно объединять `grep`, `awk`, `sort`, `uniq` и `wc`.

### **5. Управление процессами**

Для управления процессами полезны следующие команды:

```
ps
ps aux
jobs
kill
```

Символ `&` позволяет запустить команду в фоновом режиме.

Переменная `$!` содержит PID последнего фонового процесса, запущенного текущей оболочкой.

Для проверки конкретного процесса можно использовать `ps -p` с его PID.

### **6. Разработка Bash-скрипта**

Начало скрипта:

```
#!/usr/bin/env bash
```

Для проверки существования файлов можно использовать условные выражения с `-f`, а для каталогов — с `-d`.

Команда `chmod +x` позволяет установить право на выполнение скрипта.

При разработке необходимо учитывать корректность относительных и абсолютных путей, обработку ошибок и возможность многократного запуска.

## **Советы по улучшению работы**

1\. **Использование переменных.** Для путей к исходным данным и отчётам рекомендуется использовать переменные Bash вместо многократного повторения одних и тех же строк.

2\. **Обработка ошибок.** Следует предусмотреть ситуацию, когда исходный файл отсутствует, недоступен для чтения или не содержит записей.

3\. **Повышение читаемости.** Скрипт рекомендуется разделить на логические блоки и снабдить короткими комментариями, поясняющими назначение отдельных операций.

4\. **Снижение количества лишних операций.** Там, где это возможно, рекомендуется использовать `awk` для выполнения нескольких вычислений за один проход по файлу.

5\. **Автоматическая запись времени анализа.** В итоговый отчёт можно добавить дату и время запуска скрипта с помощью `date`.

6\. **Проверка на разных данных.** После успешной обработки тестового журнала можно дополнить его новыми событиями и убедиться, что статистика пересчитывается автоматически.

7\. **Улучшение переносимости.** Следует учитывать, что некоторые параметры стандартных команд могут различаться между дистрибутивами Linux и UNIX-подобными системами.

8\. **Проверка качества скрипта.** Можно использовать `bash -n` для проверки синтаксиса без выполнения скрипта, а `bash -x` — для отслеживания последовательности выполняемых команд.
