# **Практическое задание № 2. Разработка интерактивного Bash-скрипта для управления задачами**

**Модуль 2. Основы Bash-скриптинга**

## **Цель**

Освоить основные конструкции языка Bash и научиться применять их для разработки скриптов автоматизации с интерактивным управлением.

В ходе практической работы необходимо:

- Научиться создавать переменные, использовать параметры командной строки и обрабатывать пользовательский ввод.
- Освоить условные конструкции `if-else` и `case` для проверки данных и выбора действий.
- Научиться применять циклы `for`, `while` и `until` для повторения операций и обработки наборов данных.
- Освоить работу с индексированными массивами Bash.
- Научиться создавать функции, передавать им аргументы и использовать результаты их работы.
- Разработать консольную программу, которая сохраняет задачи в файл и восстанавливает их при повторном запуске.

## **Задание (шаги)**

### **Шаг 1. Подготовка проекта и создание переменных**

**Ожидаемый результат:** Скрипт запускается из терминала, принимает параметры и корректно определяет путь к файлу с данными.

### **Шаг 3. Работа с массивами и добавление задач**

Необходимо организовать хранение задач с использованием массивов Bash.

Каждая задача должна содержать три характеристики:

| Поле      | Описание                 | Пример             |
| --------- | ------------------------ | ------------------ |
| Название  | Текст задачи             | Изучить циклы Bash |
| Приоритет | Число от 1 до 3          | 1                  |
| Статус    | Текущее состояние задачи | new                |

Значения приоритетов:

- `1` — высокий;
- `2` — средний;
- `3` — низкий.

Возможные статусы:

- `new` — задача не выполнена;
- `done` — задача выполнена.

Для хранения информации необходимо использовать три индексированных массива:

```
tasks=()
priorities=()
statuses=()
```

Реализовать добавление новой задачи:

1. Запрашивать название задачи.
2. Проверять, что название не является пустой строкой.
3. Запрашивать приоритет от `1` до `3`.
4. Проверять корректность введённого приоритета.
5. Добавлять название задачи в массив `tasks`.
6. Добавлять выбранный приоритет в массив `priorities`.
7. Добавлять значение `new` в массив `statuses`.
8. Выводить сообщение об успешном добавлении задачи.

Для одной задачи все три значения должны находиться под одинаковым индексом в соответствующих массивах.

**Ожидаемый результат:** Новые задачи добавляются в массивы, а некорректные данные не принимаются.

### **Шаг 4. Использование циклов for, while и until**

Необходимо реализовать обработку списка задач и повторяющихся действий с помощью трёх видов циклов.

**Часть А. Цикл for**

Реализовать вывод всех задач с помощью цикла `for`.

Пример:


**Часть Б. Цикл while**

Реализовать непрерывную работу главного меню с помощью цикла `while`.

1. Организовать повторное отображение меню после каждого действия.

4. Исключить бесконечный цикл, из которого невозможно выйти штатным способом.

**Часть В. Цикл until**

Реализовать проверку приоритета при добавлении задачи.

1. Запрашивать приоритет новой задачи.

**Ожидаемый результат:** Все три вида циклов применяются по назначению: `for` — для перебора, `while` — для работы меню, `until` — для повторного ввода до выполнения условия.

## **Подсказки по ключевым частям**

### **1. Переменные и параметры командной строки**

В Bash присваивание значений переменным выполняется без пробелов вокруг знака `=`.

```
app_name="Task Manager"
version="1.0"

echo "$app_name"
```

Специальные параметры:

| Параметр | Назначение                            |
| -------- | ------------------------------------- |
| `$0`     | Имя запущенного скрипта               |
| `$1`     | Первый аргумент                       |
| `$2`     | Второй аргумент                       |
| `$#`     | Количество переданных аргументов      |
| `"$@"`   | Все аргументы с сохранением их границ |
| `$?`     | Код завершения предыдущей команды     |

При использовании переменных с путями рекомендуется заключать их в двойные кавычки.

### **2. Условные конструкции**

Для проверки условий можно использовать следующую структуру:

```
if [[ условие ]]; then
    # Действия при выполнении условия
elif [[ другое_условие ]]; then
    # Альтернативные действия
else
    # Действия в остальных случаях
fi
```

Полезные операторы:

| Оператор | Назначение                            |
| -------- | ------------------------------------- | --- | -------------- |
| `-f`     | Проверка существования обычного файла |
| `-d`     | Проверка существования каталога       |
| `-z`     | Проверка пустой строки                |
| `-n`     | Проверка непустой строки              |
| `-eq`    | Числовое равенство                    |
| `-gt`    | Больше                                |
| `-lt`    | Меньше                                |
| `&&`     | Логическое И                          |
| `\\      | \\                                    | `   | Логическое ИЛИ |

При проверке числовых значений необходимо сначала убедиться, что пользователь ввёл допустимое число.

### **3. Конструкция case**

`case` удобно использовать, когда необходимо выбрать одно действие из нескольких возможных.

```
case "$action" in
    start)
        echo "Запуск"
        ;;
    stop)
        echo "Остановка"
        ;;
    *)
        echo "Неизвестная команда"
        ;;
esac
```

Ветка `*` позволяет обработать значения, которые не соответствуют другим вариантам.

### **4. Циклы**

Цикл `for` используется для перебора элементов или последовательностей.

```
for i in 1 2 3 4 5; do
    echo "$i"
done
```

Цикл `while` повторяет действия, пока условие истинно.

```
counter=1

while [[ $counter -le 5 ]]; do
    echo "$counter"
    ((counter += 1))
done
```

Цикл `until` повторяет действия, пока условие остаётся ложным.

```
number=0

until [[ $number -eq 5 ]]; do
    read -r -p "Введите число 5: " number
done
```

Для завершения цикла можно использовать `break`, а для перехода к следующей итерации — `continue`.

### **5. Функции**

Функции позволяют выделять повторно используемые операции в отдельные блоки кода.

```
show_message() {
    local message="$1"
    echo "$message"
}

show_message "Операция выполнена"
```

Ключевое слово `local` позволяет объявлять переменные, область видимости которых ограничена функцией.

Для обозначения успешного выполнения и ошибок используются коды завершения, передаваемые через `return`.

### **6. Массивы**

В Bash индексация обычных массивов начинается с нуля.

```
tasks=("Изучить Bash" "Создать скрипт")

echo "${tasks[0]}"
echo "${tasks[1]}"
echo "${#tasks[@]}"
```

Выражение `${#tasks[@]}` возвращает количество элементов массива.

Для добавления элемента:

```
tasks+=("Проверить программу")
```

При работе с несколькими связанными массивами важно сохранять одинаковый порядок элементов.

### **7. Чтение данных из файла**

Для последовательного чтения строк файла можно использовать:

```
while IFS= read -r line; do
    echo "$line"
done < data/tasks.txt
```

Конструкция `IFS= read -r` позволяет сохранить пробелы и специальные символы при чтении строки.

Для разделения полей по символу `|` можно указать соответствующий разделитель через `IFS`.

При сохранении данных необходимо использовать перенаправление вывода `>` или `>>` в зависимости от требуемого поведения.

**На проверку предоставляются:** каталог `bash_task_manager`, содержащий `task_manager.sh`, файл `data/tasks.txt` с минимум тремя тестовыми задачами и файл `reports/test_results.txt` с кратким описанием выполненных проверок и их результатов.

## **Советы по улучшению работы**

1. **Разделение ответственности.** Каждая функция должна выполнять одну логически завершённую задачу. Не рекомендуется размещать всю программу внутри одного большого цикла или одной функции.
2. **Понятные имена переменных.** Использование названий `task_name`, `task_priority`, `task_status` делает код понятнее, чем использование односимвольных переменных без необходимости.
3. **Корректная обработка пользовательского ввода.** Необходимо проверять не только диапазон чисел, но и тип вводимых данных. Например, строка `abc` не должна приниматься вместо номера задачи.
4. **Использование локальных переменных.** Переменные, необходимые только внутри функции, рекомендуется объявлять с помощью `local`, чтобы избежать случайного изменения глобальных данных.
5. **Минимизация дублирования.** Повторяющиеся операции следует выносить в функции. Например, проверку номера задачи можно оформить отдельной вспомогательной функцией.
6. **Надёжное сохранение данных.** Для повышения надёжности можно сначала записывать задачи во временный файл, а затем заменять им основной файл после успешного завершения записи.
7. **Расширение функциональности.** После выполнения обязательной части можно добавить удаление задач, редактирование названий, фильтрацию по статусу и приоритету, а также сортировку списка.
8. **Повышение удобства интерфейса.** Можно добавить цветовое выделение выполненных задач и сообщений об ошибках с помощью ANSI-последовательностей.
9. **Проверка скрипта.** Для поиска проблем с синтаксисом и переменными рекомендуется использовать `bash -n`, `bash -x` и, при наличии, ShellCheck.
